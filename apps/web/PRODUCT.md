# Product

## Platform

web

## Users

主要用户是客户单位的 Boss 与 FM。Boss 需要快速知道哪里值得关注、影响多大、下一步做什么；FM 需要继续下钻到项目节点和计量点，核查建议与原始证据。

Tuya Partner Operator 和我方 Platform Admin 负责配置 Workspace、Project 结构、数据源、计量点映射和模板发布。MVP 不把这些后台能力放入客户主导航。

## Product Purpose

EnergyIQ 将每日同步的 Tuya API 或 Excel 累计计量数据，转化为可信、可复跑、可追溯的周期能源分析。用户不需要理解累计读数、SQL、Agent 或数据处理流程，也能得到口径一致的决策建议，并可继续用自然语言问数。

## Core Surfaces

1. **Analysis**：项目专属决策看板。先显示建议、异常和影响，再提供趋势、排名与证据。
2. **Project Explorer**：按项目实际硬件层级浏览节点和计量点。层级不固定，计量点可挂在任意节点。
3. **Energy Analyst**：在当前 Workspace、Project、时间段和计量范围内自由问数，通过 Task Console 展示数据核验、证据和输出预览。

MVP 使用一个 Boss-first 的客户体验。FM 不需要另一套独立前端，而是在同一页面中获得更深的下钻与证据。

## Positioning

EnergyIQ 不是通用 BI，也不是暴露 Agent 基础设施的 AI 工作台。它由稳定的项目专属模板提供可复跑分析，由 AI 问数提供灵活探索；两者共用同一事实层、时间语义、指标和访问边界。

## Brand Personality

克制、专业、可信。界面直接说明数据覆盖、结果完整度和计算来源；不使用夸张 AI 语言，不用装饰性图表制造“数据感”。

## Design Principles

1. 建议先行，图表和数字用于证明建议。
2. 每条建议都包含事实、基线、影响、可能原因、建议动作和证据来源。
3. “可能原因”必须标记为假设；仅凭电表数据不得断言“灯未关闭”等现场事实。
4. 一个页面服务一个主要任务，客户导航只保留三个核心入口。
5. 项目结构由现场硬件决定，界面不得假定固定的 Block、Level、Room 深度。
6. 电和水共用计量模型；只展示已配置资源。碳排放仅预留。
7. 默认优先与自身历史基线比较；面积和人数可靠时才提供单位面积或人均对比。
8. 固定分析和 AI 回答必须共用数据事实、指标定义和时间口径。
9. 运行自动保存且历史不可覆盖；AI 只能生成模板变更草案，不能直接发布。
10. 客户可见的是可验证的数据处理步骤，不展示模型私有推理；Knowledge、Datasource 和 Agent 配置属于后台能力。

## Accessibility & Inclusion

核心流程支持键盘操作、清晰焦点、语义化标签和屏幕阅读器。状态不能只依赖颜色表达。桌面端优先，同时保证平板和移动 Web 可以查看建议、下钻和问数。

# 双角色、用户动线与管理后台

## 决定

首期只保留：

- **user**：FM 与 Boss；
- **admin**：我方后台人员，首期也可以覆盖 Tuya 实施人员。

FM 与 Boss 使用相同页面、相同事实和相同数据权限。Boss 典型从 Overview 看建议；FM 更常从 Explorer 核查。差异是动线，不是两套账户权限。

未来只有出现真实边界后再升级：

- 一个 FM 只能看部分 Project/Scope；
- Tuya 可以配置客户项目但不能管理全局模型和密钥；
- 客户要求共享与私有分析内容分离；
- 需要跨 Workspace 批量运维。

## user 能做什么

- 切换其有 Membership 的 Organisation，并查看该 Organisation 内全部已发布 Project；
- 选择时间和资源，运行 Overview；
- 在 Project Explorer 下钻并核查 Scope、Meter、来源读数和数据健康；比较与行动建议在 Overview 查看；
- 进入 AI Analyst 继续追问；
- 查看 Task Console、Evidence、引用和只读 Data Map；
- 管理个人 Chat Session 与 My Assets；
- 不能修改 Project、Tier、Mapping、规则、正式数据或模板。

## admin 能做什么

admin 拥有 user 全部能力，并负责：

- 创建账户、Workspace Membership 和 Project；
- 配置 Tier、节点、属性和业务别名；
- 绑定实体表、总分表、业务分类和虚拟表；
- 导入 Excel、维护 Tuya Connector、查看质量；
- 配置营业日历、费率、Metric 和 Rule；
- 编辑、预览和发布 Project/Tier Template；
- 查看 Analysis Run、Evidence、Trace 和发布审计；
- 管理 DataFoundry 的 Models、Skills、Tools、MCP、Knowledge、Assets、Data Sources 和 Data Map。

## 账户开通与 Organisation 归属

- 继续复用 Data Foundry 原有用户、密码、Session、重置密码与审计能力，不建立第二套认证；
- 公开注册关闭，账号只能由 admin 在 `Access → Users` 邀请；
- 邀请链接 7 天有效；重发邀请后旧链接立即失效；用户设置姓名和至少 8 位密码后自动登录；
- 登录 MVP 只使用 email，email 大小写不敏感且全局唯一；用户名登录延后；
- 一个 user 可属于多个 Organisation；Membership 自动授予该 Organisation 内全部 `published` Project；
- `draft` / 未发布 Project 只对 admin 可见；移除 Membership 只移除对应 Organisation 的访问；
- 停用 user 会撤销其全部 Session，但保留会话、运行与审计记录；
- Personal Workspace 仅服务 My Assets，不出现在 Organisation 选择器；
- 登录后 admin 默认进入 Admin Overview，user 默认进入最近使用的 Project Overview；安全的 EnergyIQ `returnTo` 优先。

顶栏采用两级选择：

```text
Organisation selector → Project selector
```

Project 选择按 Organisation 独立保存。失效或已无权限的本地 Organisation 选择会自动清除并回退到第一个可访问 Organisation，不能把旧浏览器状态当作权限依据。

## 客户上下文传递

Overview、Explorer 和 AI Analyst 共用可信 Energy Query Context。客户端可以提交选择，但服务端必须重新解析：

~~~ts
type EnergyQueryContext = {
  workspaceId: string;
  projectId: string;
  scopeId: string;
  tierDefinitionId?: string;
  resource: "electricity" | "water";
  timezone: string;
  from: string;
  to: string;
  hierarchyRevisionId: string;
  meterFormulaRevisionId: string;
  dataSnapshotId: string;
  metricVersion: string;
  ruleVersion?: string;
  templateRevisionId?: string;
};
~~~

URL 只负责导航，不是权限依据。

## 为什么复用完整 AI 工作台

Overview 和 Explorer 的 Investigate with AI 跳到完整 AI Analyst，并携带 Project、Scope、Time Range、Resource 和有关版本。不上第二套完整弹窗，因为完整分析需要：

- 会话与追问；
- 表格、图表和 Artifact Preview；
- Task Console；
- Evidence 与 Trace；
- 文件和引用。

未来可加单轮快捷浮层，但继续分析仍回到完整工作台。

## Admin 信息架构

Admin 左侧导航按管理员的工作对象分组，而不是按一次数据导入的步骤分组：

~~~text
Overview

Access
├── Organisations
└── Users

Projects
├── Project Overview
├── Structure
├── Data Sources
├── Meter Mapping
├── Data Map
├── Templates
├── Knowledge
└── Assets

AI Operations
├── Runs & Replays
├── Conversations & Queries
├── Usage & Cost
└── Traces

AI Configuration
├── Models & Routing
├── Skills
├── Tools
└── MCP
~~~

- `Overview` 是跨 Project 的工作台，只显示需要管理员处理的事项；
- `Project Overview` 协调一个 Project 的五阶段交付进度和下一步动作；
- 具体配置只在 Projects 下的专业页面完成；
- `Data Sources` 必须先于 `Meter Mapping`；Virtual Meter 是 Meter Mapping 内的可选配置，不单独占一个 Tab；
- 上述旧导航分组不再作为正式信息架构；未接通能力仍须明确显示 Later，不伪装为可操作功能。

Project 配置仍遵循五个交付阶段：

~~~text
Basics → Structure → Data & Meters → Analysis → Review & Publish
~~~

五阶段是交付进度，不是第二套侧栏导航。管理员先从 Project Overview 判断当前阶段，再进入对应专业页面。

Project 生命周期：

~~~text
Draft → Data connected → Mapping valid → Template ready → Published
~~~

后台重点是让 admin 容易理解和配置，不使用需要学习 BI 建模语言的自由画布。Draft 允许未完成；Validate/Publish 才集中显示缺失、警告和阻断项。

### Platform & Operations

复用 DataFoundry：

- Accounts；
- Models 与 fallback 顺序；
- Skills；
- Tools；
- MCP；
- Knowledge；
- Assets；
- Data Sources；
- Data Map。

逐步增加 Operations：

- 数据同步和导入异常；
- 用户复跑统计；
- 用户典型 query；
- 模型与 token 用量；
- AI Session Trace；
- 模板发布和失败 Run。

首期可先做可筛选列表与详情，不做监控大屏。

## Knowledge、Assets 与可见性

- user 可看到回答使用的 Knowledge 引用；
- admin 可看完整知识正文、索引状态和版本；
- My Assets 是个人临时上传，不自动成为 Project Data；
- admin 可把个人文件提升为 Project Data 或 Project Knowledge；
- Energy Fact、Tier、Mapping、Metric 和 Rule 必须存结构化系统，不塞进向量库。

MVP 普通 Runs/Trace GET 只返回 redacted manifest/status。**目标能力、当前未实现**的 `View conversation` action 将允许 Project Admin 为排错查看 exact Project 下客户本来可见的 user/assistant transcript，并在隐私说明中告知；该能力不返回 System Prompt、动态 Context、Knowledge 原文、Tool arguments/results、Provider options、secret、内部路径、隐藏推理或完整模型请求。Project Admin 不能调用 Protected Request raw reconstruct。

## 明确不做

- FM/Boss 两套 UI 或权限；
- 设备级、字段级 ACL；
- partner_admin；
- AI 自动发布模板；
- 后台 CRM、工单、计费和复杂监控墙。

# 报告分析与项目风格隔离

用户确认：共享呈现规则、项目分析方法、项目视觉风格分别管理。

## 产品合同

- 通用呈现 Skill 管全英文、结论前置、证据可读性、响应式和交互有效性，不承载某个客户的配色或品牌外观。
- 分析 Skill 管问题、比较、探索、证据与建议。默认 Skill Creator 仅提取或更新分析方法。
- 项目风格 Skill 管配色、字体、版式和参考外观。Project 通过独立 `styleSkill` 绑定一份明确版本的内容快照。分析选择、分析默认版本更新、普通设置保存均保留该绑定。
- 修改或新建视觉 Skill 必须明确提出风格需求；保存版本不自动启用。管理员在 Skills 中点击“Use this report style”才更换当前项目的绑定。其他项目不受影响。
- 跨项目资源不可直接加载；未来复用样式须明确复制到目标项目并绑定，不能扩大租户访问范围。
- 每次运行包含 `project-style.md`、内容摘要和版本记录。对话任务及定时任务都冻结当次绑定，已生成 HTML 保持原样。
- 对遗留分析 Skill 内的视觉要求，以独立项目风格为准；迁移时同时抽离旧视觉段落，减少互相冲突的指令。

## 本次迁移

Tuya 根据 Charles 原报告建立橙色、白底、约 880px 阅读列的独立风格；Preschool 根据其原报告建立蓝色组合报告风格。参考 HTML 的历史读数、CDN 依赖、项目事实不能作为新报告的数据或运行依赖。

迁移通过现有受权报告 API 保存和绑定版本，保留原 settings 备份和 Skill 历史。仅迁移两个明确项目，不修改配置、数据源、电表映射或报告自动化频率。

## 验证边界

覆盖：分析更新不改变风格、显式分析选择保留风格、旧任务冻结旧版本、跨项目绑定拒绝、真实输入文件和摘要一致、前端分析选择器不混入风格。

单元测试证明隔离和加载合同，不证明模型稳定遵循版式。上线后必须实际生成新报告，核对加载文件与渲染结果；旧配置下已经成功的报告不算本次视觉验收。

# Agent 项目初始化、Skill 权限与复用产品基线

## 1. 当前决定与适用范围

这是用户于 2026-09-12 确认的新版产品基线。后续 Agent 先读本文，再读对应实现。本文的 accepted 表示产品决定已确认，不表示所有能力已经实现或生产验收完成。

新版主线：Admin 提供资料 → Agent 建立项目与数据连接 → 配置成员 → 用户对话分析与生成英文 HTML → 满意后保存报告方法 → 按周期生成新报告 → 从有效方法提取建筑类型共性。

继续在 EnergyIQ 上开发，复用账号、Workspace、Project、数据接入、已发布配置和 Explorer。Pi 是当前报告执行器；无需为此重新建设通用平台。旧 Overview/模板/AI Slot 保留为旧版能力，不再限制新版完整 HTML 报告。旧文档中“结构化模板是核心”“禁止 AI 完整生成 HTML”仅适用于旧版路径，不得套用到新报告工作台。

## 2. 选项与取舍

| 选项 | 结果 | 决定 |
| --- | --- | --- |
| 继续让 Admin 填写所有映射与层级表单 | 配置可控，但操作成本高、扩展依赖开发 | 不作为新版主要入口 |
| Agent 通过受约束工具维护同一套配置 | 资料和自然语言驱动，保留数据一致性与版本 | 采用 |
| Agent 任意写数据库或让 HTML 自己充当配置 | 无法稳定服务 Explorer、权限和历史复跑 | 不采用 |

目标是不需要人逐项填写配置表，不是禁止询问缺失信息。资料不足时 Agent 应报告问题，请 Admin 补充，不得猜测后标为确认。

## 3. 新项目初始化

### 3.1 入口与状态

项目选择器底部提供管理员专属的“Create project”，包括当前组织没有项目时。第一步明确所属客户 Workspace，输入项目名称；时区默认 Asia/Singapore。新建 Draft 后直接进入项目初始化对话，不要求用户选择 Tier 或逐行映射。

状态应区分：项目已创建、等待资料、分析资料、需要补充、配置草稿就绪、数据可用、可生成报告。保存草稿不等于发布成功，报告也不能把未经发布的计量关系当成正式数据。

### 3.2 输入及 Agent 责任

支持 CSV/Excel、API 说明与连接资料，以及 PPT/PDF/Word/图片等辅助文件；每种解析器能力单独验证，不得把上传成功等同于内容可读。当前是否支持某格式以实际解析工具为准。

Agent 负责读取文件、识别时间戳/单位/累计量或区间量、整理电表与空间、建立映射、提出计量汇总路线，维护营业时间和有来源的电价等。API 文档是资料，不是可直接执行的可信代码。凭据通过独立安全入口保存，Skill、聊天摘要和项目配置不包含密钥。

有问题时提供易懂的待补清单：缺什么、影响什么、现在可以做什么。例如：缺电价仍可分析 kWh，但不计算费用；缺面积仍可比较总量，但不输出 EUI；未知电表归属应标记未确认，不能凭 ID 编造房间。

API 项目在初始化时配置计划、增量游标、幂等导入、失败记录/重试，并验证一次实际取数与落库。静态文件不会自行产生新数据；允许后续追加上传，不能把周期报告误说成数据自动更新。

### 3.3 项目资料和呈现

结构化配置以既有规范 JSON/业务记录为权威；长说明可用 Markdown。两者相互引用，不能出现由不同入口维护的冲突事实。前端渲染概览、中心/电表数量、层级、数据覆盖、营业日历与待补信息，不让普通用户阅读 JSON。

Agent 使用和 Admin 表单相同的配置服务与校验。提供读取、草稿修改、验证、导入和发布能力，使用修订号防止并发覆盖。原表单先退为维护入口；只有 Agent 已覆盖同等能力并通过实际验证后，才隐藏对应表单。删除表单不等于删除底层服务。

首次创建与发布属于 Admin 授权的初始化流程，可以由 Agent 推进；已有项目中会改变汇总口径、删除设备或重绑数据源的修改需要展示影响及差异，不能由普通报告对话隐式执行。

## 4. 数据规模与项目上下文

CSV/Excel 是来源与分析交换格式；DuckDB 是当前统一查询底座。Explorer 和 Agent 必须来自同一份授权项目数据和配置版本。无需为了格式统一，强制浏览器或模型直接连接数据库。

目前按选定时间导出明细，超过 16 MiB 的系统 CSV 使用无损 gzip，并保留原始/压缩后大小与校验值。这解决传输体积，不等于解决无限数据的计算、内存、上下文和执行时长。

下一步为 Agent 提供一致的数据工具：读取目录与覆盖 → 按中心/电表/时间查询汇总 → 按问题取细节。结果过大写入沙盒文件，工具只返回摘要、行数、路径和覆盖；支持分块 CSV 或 Parquet。保留原始明细，不以抽样替代完整总量。查询在服务端绑定身份、Project、数据版本和窗口，沙盒不接收数据库凭据，也不获得全租户数据库文件。

默认给 Agent 的上下文是：项目配置/说明、数据目录与覆盖、当前分析范围、选择的分析方法和 HTML 呈现方法。不是把所有读数塞进聊天上下文。跨年度或多中心任务先聚合、再下钻，必要时分阶段运行，最终核对汇总与明细。

Tuya 的源数据不保证包含业务位置、用途或父子关系。位置与归属由项目资料、PPT、映射表及确认结果建立。当前报告输入中的 project-configuration.json、manifest 的 hierarchy/meterAttachments，以及明细中的业务名/父级/汇总资格来自已发布配置，不是模型猜测。虚拟电表与父子表不能重复计入官方总量。

## 5. 账号、Session 与权限

Workspace 是客户组织的隔离边界，Project 属于 Workspace。用户通过 Membership 加入授权项目；一个人可参与多个项目。邀请链接让客户自行设置密码，避免共享账号密码。

目标角色：平台 Admin 管创建与成员；项目负责人管理公共方法、公共报告和计划；成员管理个人对话和产物。不得把目前的 admin/user 枚举等同于目标角色已落地。

Session 绑定 Workspace、Project、创建用户和用途；Agent runtime 的内部 Session/进程 ID 映射到业务 Session，不单独建立一套 Agent 账号。服务端对每次调用验证权限，不依赖侧栏隐藏。未来用户聊天开放必须与这些检查一起发布。

## 6. Skill 分类、版本和避免膨胀

两个独立维度：职责（分析方法、HTML 呈现、Skill Creator/其他工具流程）；适用范围（通用/建筑类型、项目公共、个人）。项目事实如面积、电价、设备名称和营业时间留在项目资料，不复制进可复用方法。

公共或个人由作用范围与权限确定，不由“是谁聊天产生的”自动确定。Charles 可以显式保存为项目公共方法，也可做私人试验。成员默认创建个人方法，不能覆盖公共方法，可以提交改进建议给负责人。

默认一个 Project 一份主要报告方法，可有少量明确不同用途的方法；版本更新不新增一个独立 Skill。不会每次对话都自动生成 Skill。每次运行明确解析所用方法和版本；仅加载当前任务必要内容，不把全库拼进上下文。

Skill Creator 的输入包括相关对话、确认过的报告、用户反馈和项目事实引用。产物记录分析步骤、所需输入、适用条件、HTML 结构偏好和待验证限制。满意报告后“Save report method”，默认更新同一方法，保存来源关联及版本。个人定制不自动进入公共方法。

目标数据关系：Skill 定义(id, scope, workspace/project/owner, category, buildingType, requirements) → 不可变 Revision(content, sourceSession/report, evaluation) → Project binding/个人偏好 → Run 已解析的版本集合。来源 Session 是追溯关系，不是唯一使用范围。

## 7. Knowledge 与公共/个人自动化

Knowledge 是统一产物入口，不代表全项目可见。个人对话产物默认私有，可显式分享给 Project；公共报告向授权成员开放。下载、预览和再次对话都执行相同的服务端权限检查。已有报告迁移须保留原可见性，不静默扩大或缩小访问。

Schedule 绑定 Workspace、Project、所有者/执行身份、public/private 范围、方法版本、时间窗口规则、周期、时区和产物可见性。普通成员不能修改公共计划。Owner 权限失效时暂停，不继续使用失效身份执行。

公共 Skill 新版本先试跑再切换公共计划，个人版本不会影响它。运行固定数据/配置/方法版本，历史报告保留；支持新建报告或参考旧报告修订，但新窗口数字必须重新计算。重复触发幂等，失败可重试，有清晰状态。

周期分析保留主线和比较基础，同时允许新发现：变化、异常候选、影响、建议、证据与待核实假设。不得把电耗增加等同于人流增加，除非确实有相关传感器数据。

## 8. 方法飞轮

项目实践 → 用户反馈 → 方法改进 → 提取共性 → 在其他项目验证 → 更新方法库。不是保存更多文件就会自动进化。

优先沉淀学校、多中心 Preschool、办公室等方法，记录适用类型、所需数据、验证过的项目、效果和局限。共享的是脱离客户私有数据的工作方法；不跨租户泄露设备名、原始读数、聊天和专属资料。

新项目按类型、数据粒度、覆盖、可用电表与资料选择方法。先自动生成有价值初稿，逐步减少人为引导；效果稳定后才扩大自动化。Skill 不应限制新的研究角度，但新方法先作为候选验证，不能自动改全库。

## 9. 实施顺序与验收

| 阶段 | 工作 | 依赖 | 验收 |
| --- | --- | --- | --- |
| A（现在） | 创建项目入口、初始化对话、结构/资料/待补信息工具 | 现有项目创建和配置服务 | 空项目可创建进入独立对话；Agent 知道未就绪原因；权限与旧项目不变 |
| B | 文件/API 导入、映射、验证、发布与定时更新完整闭环 | A | 用新项目资料实际跑到 Explorer 和报告读取同一批数据；缺信息可恢复继续 |
| C | 项目成员、个人/公共 Skill 和产物范围、用户聊天 | A 的身份契约，可与 B 分模块推进 | 两个用户跨账号验证隔离、分享与负责人权限；旧报告迁移明确 |
| D | 方法保存/版本/试跑/公共个人计划 | B+C | 不同时间段复跑，新报告按正确范围展示，重复触发不重复交付 |
| E | 方法评估、类型归纳、新项目匹配 | D 及足够真实反馈 | 留出未参与归纳的新项目验证首报价值，不能只评价 HTML 可生成 |

本轮开发从 A 开始。B–E 是已确认目标，但尚未宣称完成。BI、报告内追问、第三方工具市场等不阻塞 A–D。

2026-09-12 后续进展：阶段 B 的现有支持格式 Excel 链路已用真实资料在新建本地项目验证，包含导入、映射、发布、Explorer 与报告同源读取。通用 CSV 适配和任意新 API 自动配置仍未完成，C–E 也不能据此视为完成。详见 [真实初始化验收记录](../records/2026-09-12-agent-project-onboarding-live-validation.md)。

## 10. 现状和停止条件

截至本决策起点：线上已有 Pi + deepseek-flash、项目数据窗口导出、英文 HTML/Knowledge；Tuya/Ngee Ann/Preschool 已有验证报告。Admin 项目工具支持配置草稿、说明与日历/电价的非激活修订；新项目全链初始化、普通成员聊天、个人/公共 Skill 与计划并未完整落地。

若发生跨项目访问、错误计量汇总、源数据未落库却宣称初始化成功，优先修复。非阻塞 UI 小问题记录后继续。方法价值由用户反馈验证，不能以测试通过替代 Charles 验收。

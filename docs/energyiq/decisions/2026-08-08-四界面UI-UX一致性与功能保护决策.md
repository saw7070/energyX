# EnergyIQ 四界面 UI/UX 一致性与功能保护决策

## 1. 背景

Overview、AI Analyst、Project Explorer 与 Admin 已经共享 EnergyIQ 顶栏、黑白中性视觉和基础组件，但页面骨架、字号、侧栏、状态和内容层级仍像四套分别开发的工具。用户切换页面时需要重新理解布局，也容易被小字号、永久辅助文字和同权信息分散注意力。

本次工作只优化展示与操作体验，不改变确定性指标、时间窗口、Snapshot/Evidence、AI 工具链、Session、项目层级或 Admin 配置语义。功能正确性优先于视觉一致性；若统一样式需要破坏现有行为，则停止该项统一。

## 2. 选项

| 选项 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A：强制同构 | 四个页面使用同一套侧栏、标题和布局组件 | 表面统一、复用率高 | 无视四种任务差异，容易损害 Session、树状导航和管理流程 |
| B：继续独立 | 每个页面只做局部美化 | 风险最小、改动少 | 页面切换仍像不同产品，字号和状态问题会继续扩散 |
| C：共享视觉语法，保留功能结构 | 统一字号、间距、标题、折叠习惯、主次层级和状态规则；四类侧栏保持各自的信息结构 | 形成一个软件的体验，同时保护功能 | 需要逐界面校准，不能靠一次全局替换完成 |

## 3. 决定

**选择 C：共享视觉语法，保留功能结构。**

统一的是：

- 字号、字重、行高和可读性底线；
- 页面标题、内容边距、Sticky 起点和首屏节奏；
- 主要信息、支持信息、技术元数据的视觉层级；
- 展开/收起图标、命中区域、焦点和窄栏行为；
- Loading、Empty、Unavailable、Error 等状态的基本语言；
- 必要的桌面、Tablet 和窄屏适配。

不强制统一的是：

- Overview：无功能侧栏，只保留平级章节导航；
- AI Analyst：侧栏以 Session 搜索、选择和管理为主；
- Project Explorer：侧栏以 Project/Scope/Meter 树状导航为主；
- Admin：侧栏以管理模块、项目选择和交付流程为主。

## 4. 理由

1. 用户需要学习一次视觉规则和折叠行为，但不应因追求复用而失去符合任务的导航结构。
2. 当前最大痛点是阅读成本和信息竞争，不是缺少新功能或组件平台。
3. Overview 的章节导航、AI 的 Session、Explorer 的树和 Admin 的功能菜单具有不同语义，强制同构会降低效率。
4. 小型共享规则和展示原语足够完成 MVP，不需要建设新的通用 Design System。
5. 先建立功能保护基线，再逐切片改展示，可以把回归风险限制在可验证范围。

## 5. 执行路线

### UI-00：功能保护基线

- 记录四个界面的关键功能和当前自动测试；
- 固定不能变化的路由、查询参数、Session、树选择、Admin 项目选择和 Overview 行为；
- 每个后续切片只改展示层，并运行相关行为测试；
- 若需要修改数据合同、状态所有权或业务计算，停止并交回主 Agent。

### UI-01：字体与信息层级

- 建立正文、辅助正文、标签、技术元数据四级文字职责；
- 用户必须阅读的正文提高到舒适字号，默认不使用 10–11px；
- 10–11px 只保留给极短标签和非关键 Metadata；
- 删除只重复控件名称或用户一眼可知的说明；
- 技术信息优先折叠，不直接删除。

### UI-02：共享页面骨架

- 统一顶栏下方的标题起点、内容边距、标题/上下文关系和首屏留白；
- 统一侧栏头部高度、折叠按钮、窄栏宽度和 Sticky Offset；
- 不把四个页面强制塞入同一个页面模板。

### UI-03：四种导航按职责优化

- Overview：章节导航弱化为阅读辅助，不与内容竞争；
- AI Analyst：强化 Session 定位、选择和折叠后的恢复入口；
- Project Explorer：保持树结构、层级关系和当前节点清晰；
- Admin：保持管理分组、项目上下文和流程入口清晰；
- 四者共享相同的选中、悬停、焦点、折叠和滚动反馈。

### UI-04：主要信息与状态

- 每个页面或模块明确一个主要结果/任务和一个主要动作；
- 次要操作和技术说明降低视觉权重；
- 在不会扩大范围时，统一页面加载、局部加载、空数据、不可用和错误状态；
- 状态统一若需要改动业务状态机，则延期，不阻塞 UI-01～UI-03。

### UI-05：必要响应式与视觉验收

- 重点覆盖 1920、1440、1280 和基本窄屏；
- 桌面功能不得因响应式改动消失或改变语义；
- 验收侧栏折叠、长标题、表格/图表溢出和主要操作可达性；
- 完整无障碍专项暂缓，但不得删除已有 ARIA、Focus 或键盘能力。

## 6. 功能保护门槛

每个切片必须同时满足：

- 现有行为测试不回退；
- Overview 的 Project、Snapshot、Evidence、时间结构和保存/历史语义不变；
- AI Analyst 的 Session、Run、输入、结果恢复和 Task Console 行为不变；
- Project Explorer 的树选择、Scope/Meter 上下文、期间和精准跳转不变；
- Admin 的 Workspace/Project 上下文、配置、验证、保存和发布行为不变；
- 不对 `10px/11px` 进行全局机械替换；
- 不把四类侧栏重构成一个承担所有业务的通用组件；
- Chrome 证据和自动测试分开记录，不能互相替代。

## 7. 后果

- 界面会逐步形成一致的操作习惯，但组件复用不是完成指标；
- 部分小字和状态不会一次性全部修改，需要按用户阅读路径逐步处理；
- 四种侧栏仍可保持不同结构，只共享表现规则和低风险原语；
- 状态统一和无障碍不会阻塞首轮可读性与骨架优化；
- 未来新增页面应先选择适合任务的结构，再遵守共享视觉语法。

### 失效条件

出现以下任一情况时复审本决策：

1. 统一展示必须修改业务状态、数据合同或核心交互才能成立；
2. 新的共享组件需要大量条件分支才能容纳四种侧栏；
3. UI 改动造成 Session、树选择、Admin 保存/发布或 Overview Context 回归；
4. 为了统一而建设独立 Design System 平台，延迟客户可见效果；
5. 用户反馈表明某一界面的专业任务效率因统一风格下降。

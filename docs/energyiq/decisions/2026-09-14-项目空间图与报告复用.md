# 项目空间图与报告复用

空间关系属于项目资料，不能只存在某一份报告或分析 Skill 中。首版复用已保存的 Project notes/contextNotes 中的空间参考 JSON；这份项目资料是长期来源，Agent 通过 project_context_read/update 维护，保留 expectedRevision 并发检查及项目权限。

共享合同 `packages/contracts/src/project-spatial.ts` 验证 schemaVersion、projectId、来源、viewBox、区域和房间矩形。仅解析当前项目的有效参考块。前端以安全生成的 SVG 图片展示、支持放大，隐藏已渲染块的原始 JSON。用户仍可通过“Update notes with AI”维护。参考图不发布电表映射，不改变 Explorer 的计量口径。

每次报告任务从同一份已冻结的 contextNotes 导出 project-spatial-reference.json 和 project-spatial-reference.svg，写入 manifest.spatialReference 和 projectFiles 哈希。图中不固化某期能耗。已有 Tuya 空间资料直接适用，无需重新上传；缺乏空间资料的其他项目不虚构图。

完整报告默认在主要结论后展示精简位置图；简短回答、明确要求省略地图的简报可例外。通用呈现 Skill 规定何时引用，项目风格规定外观，审阅 Skill 检查是否遗漏、能否离线显示、空间与设备分组关系是否正确。每期的探索分析仍可变化。

首版是来源可追溯的非按比例示意图，不是测绘图。缺失房间坐标不自动猜测；后续上传正式图时，保留来源及版本并更新同一份项目资料。跨项目不共享具体空间资料。原有图上的历史耗电数字不得成为新报告读数。

验收区分代码测试、页面渲染、真实 Agent 生成及线上部署；不能将单元测试通过当作线上报告已验收。

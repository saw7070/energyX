# 2026-08-01 开发记录：Admin 首次数据源配置交互原型

> **状态：已废弃。** A/B/C 是一次局部 Data Sources 交互实验，不符合管理员从 Project 初始化、先定义 Structure、再接入数据的正式动线。`variant=A|B|C` 路由和原型代码已移除。本文件只保留历史验证证据，不能再作为开发入口或待选方案。

## 1. 目标与范围

本轮只回答一个产品问题：**管理员第一次接入 Ngee Ann 数据时，如何用尽量少的步骤完成 Excel 导入、字段与 Meter 映射、`Virtual Load 12` 确认、质量检查和发布；以后每天导入时又如何直接复用这些一次性配置？**

原型范围：

- 全英文 Admin 界面；
- 覆盖首次配置、重复导入和失败文件三条路径；
- 清楚区分 Draft、Warning、Published、Failed；
- Excel 是当前可用入口，Tuya 只作为未来共享同一 Source Adapter 契约的预留入口；
- 所有数据和状态只在浏览器内存中模拟，不写数据库、不上传文件、不调用真实 API。

本轮不改正式 Admin 信息架构，不实现 Tuya Connector，不创建真实 Setup Revision 或 Data Snapshot。

## 2. 原型改动

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| `apps/web/src/app/energyiq/admin/_prototype/source-setup-prototype.tsx` | 新增 | 三套首次数据源配置原型及本地状态机 |
| `apps/web/src/app/energyiq/admin/_prototype/prototype-switcher.tsx` | 新增 | 开发环境专用 A/B/C 方案切换器，支持方向键 |
| `apps/web/src/app/energyiq/admin/page.tsx` | 修改 | 仅在开发环境且存在 `variant=A|B|C` 时进入原型；正常 Admin 路由保持不变 |

原型入口：

- 方案 A：`http://127.0.0.1:3001/energyiq/admin?variant=A`
- 方案 B：`http://127.0.0.1:3001/energyiq/admin?variant=B`
- 方案 C：`http://127.0.0.1:3001/energyiq/admin?variant=C`

页面底部有开发专用切换器，可以直接比较三套方案。

## 3. 三套方案与推荐

| 方案 | 核心结构 | 最适合的任务 | 当前判断 |
| --- | --- | --- | --- |
| A · Guided setup | 左侧步骤、中间当前任务、右侧发布就绪状态 | 第一次接入，由管理员按顺序完成少量必要确认 | **推荐作为主流程**，最容易理解，也最符合“一次配置、以后复用” |
| B · Control room | 批次、映射、质量与发布门槛同屏 | 未来大量项目和批次的日常运维 | 信息密度高，适合后续运营页，不适合首次配置作为默认入口 |
| C · Release review | 用变更集呈现 Setup、Mapping、Virtual Formula、Quality 和 Output | 发布前复核“这次到底会改变什么” | 适合吸收到 A 的最后一步，不建议单独承担完整首次配置 |

建议的正式方向是 **A 为主，吸收 C 的发布变更摘要，B 留给未来平台运维视图**。在用户确认前，这只是推荐，不是已接受设计。

## 4. 已验证交互

### 4.1 首次配置

在方案 A 中完成：

1. 选择 Ngee Ann 示例 Excel；
2. 确认源字段 `Device Name`、`Time`、`Active Energy`；
3. 确认 9 个 Meter Mapping；
4. 确认 `Virtual Load 12 = Load 1 + Load 2`，并明确它默认不进入官方汇总；
5. 查看 7 条质量 warning 并确认；
6. 发布 `Setup r4 + first Data Snapshot`。

发布后界面明确显示：`Setup r4 and its first Data Snapshot are now immutable.`

### 4.2 重复导入

切换到 `Repeat import` 后：

- 已发布 Mapping 直接复用；
- `Virtual Load 12` 公式保留；
- 选择新 Excel 后直接进入质量检查；
- 发布动作只创建新的 Data Snapshot，不改变 `Setup r3`。

这条路径体现了当前共识：Mapping 和 Virtual Meter 通常只配置一次，日常导入不要求管理员重复确认。

### 4.3 失败恢复

勾选 `Preview failed file` 后，原型模拟缺少 `Time` 字段：

- Source Contract、Data Quality 和 Release 都进入 Failed；
- Publish 被阻止；
- 页面说明应修复文件或更新草稿 Mapping 后重试；
- 明确显示 `No Raw Reading or Fact was published.`。

## 6. 取舍与后续

- 原型使用真实源到事实契约的数量和状态口径，但不冒充真实持久化结果；
- Tuya 只显示为预留 Adapter，不提前增加 API 独有配置；
- A/B/C 不再进行胜出方案选择；正式路径以 `Project Overview → Structure → Data Sources → Meter Mapping` 为准；
- Virtual Meter 作为 Meter Mapping 内的 optional 配置，不设置独立 Tab；
- 正式实现应调用统一 Source Adapter、Setup Revision、Data Snapshot 和质量证据接口，不能复制一套前端私有状态机。

## 7. 当前替代方案

正式 Admin 使用稳定侧栏承载可到达位置，使用 Project Overview 承载交付进度。数据源详细上传、检查和失败恢复交互仍需单独确认，确认前只展示真实依赖关系，不再生成平行原型路线。

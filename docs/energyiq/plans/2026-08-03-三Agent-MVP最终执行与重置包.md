# 三 Agent MVP 最终执行与重置包

## 1. 权威性

本文是截至 2026-08-03 唯一有效的三个 Agent 派工入口。旧的三线责任文档、各 Agent Handoff、AI Delivery Route 和两份 Correction Prompt 均为 `superseded`，不能继续作为实施规格。

正式仓库只有：

    D:\Projects\energyiq-datafoundry

`D:\Projects\energyiq-rebuild` 已废弃：不维护、不参考代码、不迁移实现、不从中恢复 Deep Agents 或旧 Runtime。旧项目中属于用户且仍有效的凭证，只有在目标系统支持对应 Provider、所有权明确并通过安全录入时才可复用；不得形成运行时依赖。

## 2. 唯一产品路线

    Energy Data Foundation
       ├─ Structured Template / Overview（核心）
       └─ AI Analyst（增强）
                     ↓
              Context / Evidence 协同（后续）

第一版 MVP 必须同时完成：

1. Ngee Ann 数据稳定并形成 golden result；
2. Overview、Save、History、Rerun 和精简 Explorer 可用；
3. AI Analyst 完成可信问数、Evidence、Task Console 和基础图表。

两个功能的深度协同紧随其后，但不阻塞第一版 MVP。

## 3. 当前真实基线

### 已有

- Excel 导入、Import Batch、累计读数差分和 15 分钟事实；
- Workspace DuckDB、Ngee Ann 真实物化数据、Scoped Datasource；
- Energy Query Context 和确定性 Energy Analysis；
- Tier/Node/Meter Mapping、Virtual Meter 基础；
- Metric/Rule/Component/Template Draft 与不可变 Revision 代码；
- Admin Preview 与客户 Overview 共用 Renderer；
- DataTasksApp、Mastra、AG-UI、Task Console、Knowledge、MCP、Skills、Model Profile 和受控 Artifact。

### 尚未完成

- Ngee Ann 数据完整度最高的共同 7 日 Period 与单日样本；
- Ngee Ann golden result 和最小 Data Health 封口；
- Ngee Ann 正式 Template Revision 与完整 Overview 验收；
- Save、Saved Analysis、History、Rerun；
- Explorer 收窄为数据核查；
- 可复现的真实模型 Profile 和 Ngee Ann AI E2E；
- 十个 Boss 问题及与 Overview/golden result 的数字对齐。

## 4. 共同数据与验收

- Project：`ngee-ann-polytechnic`；
- Resource：Electricity；
- Scope：由 Agent 1 固定 Project 根及必要的 Level/Circuit 验收 Scope；
- Golden Period：Agent 1 自动选择数据完整度最高的连续 7 天；
- Golden Day：从该 Period 中选择一个完整单日验证 15 分钟/小时曲线；
- Golden Period 只用于开发对账，不限制正式用户时间选择，也不是异常历史基线；
- 三条链路在同一 `Project + Scope + Period + Metric` 下数字、单位和范围必须一致。

十个 Boss 验收问题：

1. 当前周期总用电及相对上一周期变化；
2. 是否高于自身历史正常水平及差值；
3. 工作日、周末和公共假期模式差异；
4. 用电最高的 Level/区域/房间；
5. 可靠面积/人数元数据下的归一化表现；
6. 主要 Circuit 和贡献度；
7. Light、Load、Aircon、Other 构成；
8. 峰值时间和贡献 Circuit；
9. 非营业时间用电与可避免浪费；
10. 最优先处理的三个问题、Evidence 和数据可信度。

Tariff 未配置时不回答正式费用；Carbon、Forecast 和 Water 不进入本轮。

## 5. 模型决定与密钥规则

1. 默认主模型：DeepSeek `deepseek-v4-pro`，官方 OpenAI-compatible Base URL 为 `https://api.deepseek.com`；
2. 先用 `deepseek-v4-pro` 跑通完整 E2E；
3. 跨 Provider fallback：阿里云百炼 `qwen3.7-max-2026-06-08`；`deepseek-v4-flash` 可作为同 Provider 的低成本/低延迟选项；
4. fallback 只在 `deepseek-v4-pro` 已通过验收后启用，避免首轮排错无法确认实际模型；
5. Claude 暂不使用：当前 DataFoundry Provider 只支持 OpenAI-compatible，原生 Anthropic Adapter 后置；
6. API Key 只能通过 DataFoundry 加密 Model Configuration 本地录入并执行 `Test connection`；
7. 聊天中已经出现的 Qwen 和 DeepSeek Key 均视为暴露，必须撤销并重新生成；
8. 任何 Prompt、文档、日志、测试 fixture、`.env.example`、源代码和 Git 都不得出现真实 Key。

2026-08-03 真实验证结论：Qwen、DeepSeek V4 Pro 和 V4 Flash 的远端鉴权及文本调用均成功；DeepSeek V4 Pro 完成了自动工具调用、工具结果回传和最终回答。当前仓库仍有一个本地依赖阻塞：根 `@ai-sdk/openai 3.x` 产生模型协议 v3，但根目录被旧 CopilotKit 依赖提升成了 `ai 5.x`，因此直接调用只接受协议 v2；`npm ls` 也明确报告依赖树 invalid。Mastra 1.46 同时带有 AI SDK 5/6 兼容层，其 `chat` 依赖要求 `ai ^6.0.182`，所以上游实际是升级了一半，并非 DataFoundry 自己的旧模型协议。

正式修复使用成熟 Provider 生态，不自研协议：为 Mastra 主链显式安装/锁定 AI SDK 6；CopilotKit 子树保留自己的 AI SDK 5；DeepSeek 使用与 AI SDK 6 对应的官方 `@ai-sdk/deepseek@ai-v6`，Qwen 使用 `@ai-sdk/alibaba@ai-v6`，其他兼容厂商使用 `@ai-sdk/openai-compatible@ai-v6`。DataFoundry 只保留 Model Profile → Provider Registry 的薄映射和加密 Secret，不复制各厂商 HTTP 协议。升级后必须重新跑 Mastra、AG-UI、CopilotKit、工具调用、stream、fallback 和现有 smoke tests。

DeepSeek V4 默认开启 thinking。自动工具选择的两步 Tool → Result → Final Answer 已验证成功；若某个测试强制 `tool_choice=required`，需关闭 thinking 或改用自动工具选择，不能把该错误误判为 Key 失效。

DeepSeek 模型名与接口参考：<https://api-docs.deepseek.com/api/list-models>。

## 6. AI 查询决定

第一版完全复用 DataFoundry 原生可信查询链路：

    Energy Query Context
    → Scoped Datasource
    → inspect_schema / preview_table
    → semantic + analysis contract
    → plan / validate SQL
    → run_sql_readonly
    → result validation / evidence binding
    → answer / table / chart / Task Console

不预先开发 Energy Tool。先用 Ngee Ann 语义说明、现有 Scoped Datasource 和只读 SQL 完成十个问题，并与 golden result 对账。只有某些确定性指标反复无法与 Overview 对齐时，才允许增加一个调用现有 `executeEnergyScopeAnalysis` 的薄包装 Tool；不得复制计算公式或建设第二套分析引擎。

图表只在有助于理解时生成：时间趋势用 line，横向比较用 bar，构成用 pie，精确数字用 table。Heatmap、Quadrant、Bell Curve 和任意 React/JavaScript/ECharts 代码不进入 AI MVP。

模型不可用或数据不足时必须明确降级；不得生成 mock 答案。数据覆盖不足时只能解释数据质量，不能输出业务异常和行动结论。

## 7. Saved Analysis 边界

第一版只做：

- 手动 Save analysis；
- Saved Analysis 只读查看；
- History 列表；
- Rerun 使用最新数据创建新结果；
- 旧结果不覆盖。

PDF、定时报告、邮件发送和保存 AI 正式结果后置。

## 8. 文件 Owner 与冲突规则

| 范围 | 主 Owner |
| --- | --- |
| DuckDB、Import/Fact、Scoped Datasource、Energy Analysis、Data Health、golden fixture | Agent 1 |
| EnergyIQ Overview、Renderer、Admin Template Publish、Saved Analysis UI/领域、Explorer、产品集成 | Agent 2 |
| EnergyIQ AI Workbench、Energy Context 到 DataTasksApp、AI E2E、受控 Chart/Evidence、Model Profile 验证 | Agent 3 |

共同热点包括 `apps/api/src/energy/energy-api.ts`、`apps/api/src/server.ts`、`apps/web/src/lib/config-api/*` 和 `packages/metadata/src/index.ts`。Agent 修改共同热点前先检查其他未提交改动；存在重叠就停止并报告，不能 reset、clean、覆盖式 checkout、批量格式化或删除他人工作。

Agent 2 是最终产品集成 Owner，但不能擅自改写 Agent 1 的数据口径或 Agent 3 的 Agent Runtime。

## 9. 新需求停止规则

只立即处理：

1. 阻塞 Ngee Ann 三条主链路的问题；
2. 导致数字、单位、Scope 或 Period 不一致的问题。

其他发现只进入 backlog，包括通用指标平台、任意历史 Snapshot 重放、新 Receipt、新 Runtime、新 Task Console、Deep Agents、多 Agent、Preschool、Tuya、Water、复杂图表、PDF、定时报告和 AI 修改模板。

## 10. 统一状态回报

每个 Agent 每轮只回报：

1. 已完成；
2. 验证证据；
3. 下一步；
4. 阻塞；

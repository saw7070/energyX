# EnergyIQ 三个核心任务界面与 Data Map

## 1. 全局 Shell

顶部顺序：

~~~text
EnergyIQ | Project selector | Overview | Project Explorer | AI Analyst | Data Map | Admin* | Account
~~~

Admin 仅管理员可见。界面默认英文。Project selector 是全局上下文，切换后当前页面必须重新请求对应 Project 的内容，不能只改选择器文字。

Water 未配置时不显示资源选项。顶部始终显示数据更新时间和 provisional/stale 状态。

## 2. Overview

**任务：** 让 Boss/FM 快速知道先处理什么。

### 布局

- 左侧：粘性章节目录；
- 主区：建议、KPI、比较、时间模式和 Evidence；
- 页头：Scope、Period、Resource、Run。

左侧目录：

1. Overview；
2. Benchmarks；
3. Standby wastage；
4. Operating hours；
5. Forecast preview。

### Ngee Ann 首个 Preset 的信息顺序

1. Action Summary；
2. Data Status & Scope；
3. Energy Overview；
4. Level Comparison；
5. Day Profile & Heatmap；
6. Exceptions & Evidence；
7. Recommended Actions。

Circuit Ranking 不是独立长章节：正常情况下放在 Level Comparison 里解释 Level 差异，异常情况下放在 Exceptions & Evidence 里定位贡献回路。Forecast Preview 仍保留未来导航位置，但在历史数据和回测不足时不渲染正式结论。

- Action Summary 最多 3 条，固定使用 `Problem → Impact → Action → Evidence`；无重要异常时显示 `No priority exceptions`；
- 阻断当前分析的数据质量问题优先展示，并隐藏受影响结论；Data Status & Scope 固定在第二位且不可关闭；
- Ngee Ann 的 Level 6/7 只做绝对量、差值、自身历史和可用时的归一化描述，不用统计异常标签；
- Circuit Ranking 在每个 Level/分类下默认 Top 5，可展开全部；
- Day Profile 区分 Workday、Weekend、Public Holiday；多日默认 Date × Hour，单日默认 Level × Hour；
- Recommended Actions 只读并链接 Evidence、Explorer 或 AI Analyst，首期不做工单状态。

图表必须回答一个决策问题。没有可执行含义的炫酷图不进入模板。

### 操作

- 全局 Period 提供 Yesterday / Last 7 days / Previous week / Previous month / Custom，可按需要保留 Last 30 days；
- 选择 Scope、Resource 或 Period 后自动刷新全部模块，不创建 Analysis Run；
- 模块内可切换 15 min / Hour / Day、Compare with previous period、分类筛选和排名展开，但不能各自改变全局主时间范围；
- `Save analysis`、`Generate report` 或定时报告才创建不可变 Analysis Run；
- Project、Scope、Resource、Period、granularity、comparison 和分类筛选等状态进入 URL，刷新或分享后可恢复，但不创建 Run；
- 未保存交互不进入 Runs History，只保留请求日志；AI 交互另外进入 Session Trace；
- 保存的 Analysis Run 属于当前 Workspace，同一 Workspace 的 FM/Boss 可见，并显示创建人和创建时间；
- 每日、每周、每月调度只由 admin 配置，user 只做手动保存和报告生成；
- 首次进入默认 Last 7 days，完整周期按 Project timezone 且不含今天；无数据时显示 `View latest available data`，不静默改写 Period；
- Custom 使用 `[from, to)`，UI 结束日期包含当天；默认粒度为单日 Hour、2–31 天 Day、更长范围 Week；
- Peak 显示最高 15 分钟区间平均功率与发生时间；Coverage `<95%` 时显示部分图表但隐藏异常/建议，并禁用保存和报告；
- Save analysis 默认生成 Project · Scope · Period 标题，可改标题/备注；打开后为只读 Saved analysis；
- Explore with these settings 返回交互视图，Rerun 使用最新数据创建关联的新 Run，二者都不修改旧 Run；
- Runs History 展示名称、范围、时间、保存人/时间、数据和报告状态；报告从同一 Run 生成 HTML/PDF；
- 点击节点进入 Explorer；
- 点击 Investigate with AI 进入完整 AI Analyst。

Interactive Analysis 是用户默认交互方式：Template 固定模块和计算口径，用户自由改变查询参数。页面不再用 `Run analysis` 作为普通时间刷新按钮；失败时可以提供 Retry/Refresh，但它不等于正式 Run。

## 3. Project Explorer

**任务：** 让 FM 按项目真实结构核查“有哪些 Scope/Meter、最近收到了什么数据、这些数据是否可信”。

Explorer 是设备与数据核查台，不是第二张决策看板。它可以显示来源数据和确定性派生值，但不做跨节点业务排名、节能建议或原因判断。

### 与 Overview 的边界

| 留在 Explorer | 移到 Overview |
| --- | --- |
| Project Tree、Scope、Meter、Source Binding | 同级横向比较与排名 |
| 最新累计读数、区间能耗、数据覆盖 | 自身历史异常与跨时段判断 |
| 15 分钟/24 小时平均功率、原始与区间曲线 | Level/Room/Circuit 比较热力图 |
| Physical/Virtual、total/component/standalone | 高耗能、非营业浪费与决策异常 |
| 数据新鲜度、连接信号、Flatline、质量事件 | Possible Cause 与 Recommended Action |
| Data Snapshot、Import Batch、查询与来源证据 | 成本、节省金额和管理结论 |

单个 Meter 自身的时间曲线或数据覆盖热力图仍属于数据核查；多个节点之间的比较热力图属于 Overview。

### 桌面布局

- 左：可搜索的 Scope Tree；Meter Point 是挂载项，不是 Tier；节点旁显示汇总后的 Data Health；
- 主区页头：Breadcrumb、Scope/Meter 名称、Resource、统一 Period Selector、最后数据时间、Investigate with AI；
- 主区摘要：最新读数、所选时段能耗、24 小时平均功率、峰值区间平均功率、覆盖率；
- 主区趋势：原始累计读数与 `interval_kwh / interval_average_kw` 切换；
- 主区明细：直接挂载 Meter、来源记录、质量事件和可追溯信息。

### Scope 与 Meter 展示

选择 Project 或空间 Node 时：

- 展示直接子节点和直接/下级 Meter 的结构清单；
- 汇总所选时间段的来源数据、覆盖率和 Data Health；
- 不对兄弟节点做耗能优劣比较。

选择 Meter Point 时：

- physical/virtual 与 total/component/standalone；
- Source Binding 或虚拟表公式；
- 最新读数、最后接收时间、所选区间能耗；
- 原始累计曲线、区间能耗曲线和区间平均功率；
- Import Batch/Data Snapshot、覆盖率和质量事件。

### 数据健康状态

Explorer 分开表达连接和读数质量：

| 状态 | 表达 |
| --- | --- |
| Healthy | 绿色；最近计划同步成功，读数足够新且无阻断质量事件 |
| Delayed | 琥珀色；错过 1 次计划同步 |
| Stale / Suspected offline | 红色；连续错过 2 次计划同步且时间戳没有前进，或 API 明确返回 offline |
| Flatline | 琥珀色；连续 3 个日历日有新时间戳到达但累计读数不变，提示“零耗能或疑似卡表”，不直接宣称离线 |
| Invalid | 红色；复位、负差、单位冲突、重复冲突或不可能跳变 |
| Unknown | 灰色；尚无已接受读数或历史不足；Connectivity Unknown 单独展示 |

如果 Tuya API 提供 heartbeat/online/last_seen，则单独展示 Connectivity。正式契约未确认前 Connectivity 为 `Unknown`；只有每日 Excel/API 批次时，页面写 `Last data received` 和 `Data health`，不包装成实时在线。

树中的 Meter 显示自身状态；Scope 显示 `critical/warning` 数量。只有 Official Aggregation Route 所依赖的 Meter 为红色时 Scope 才标红，其他子表异常只把 Scope 标黄。Flatline 默认检查所有 Physical Meter，admin 可带原因静音。Virtual Meter 显示 `Derived` 而非 Online/Offline，必要输入缺失时显示 `Partial`。

### 时间与功率口径

Period Selector 与 Overview 共用 `Yesterday / Last 7 days / Last 30 days / Custom` 组件和 Project timezone 规则。Explorer 默认选择 `Latest complete data day`，即最近一个整日事实已经进入 `Available` 的日历日，并同时展示覆盖率。切换 Overview/Explorer 时保留 Project、Scope、Period 和 Resource 上下文。

左侧树的状态始终是 `Current data health`，按最新计划同步计算；主区的 Coverage/Missing/Reset 是 `Selected-period quality`，按当前 Period 计算。两者必须使用不同标题，不能用历史数据判断设备当前在线。

~~~text
interval_average_kw = interval_kwh / actual_elapsed_hours
24h_average_kw = valid_interval_kwh_sum / covered_hours
~~~

因此从累计电能推导的功率必须标为区间平均功率。只有来源明确提供瞬时有功功率时，才显示 Instantaneous active power。

### Meter 详情摘要、导出与告警

选中单个 Meter 后，顶部固定显示：Latest reading、Last data received、24h energy、24h average power、Peak interval-average power、Coverage。Voltage、Current、Power Factor 等来源可选字段放入次级 Electrical details。

- user 的 Export CSV 导出规范化 timestamp、累计读数、interval kWh、interval average kW、quality flag 和 source batch；
- admin 另可下载不可变原始 Excel/API payload；
- MVP 告警只在 Explorer 与 Admin Issue List 展示，不做邮件、短信或推送。

### Overview 上下文跳转

Overview → Explorer 保留 Project、Scope、Period、Resource 和当前 Run/Release/Snapshot；证据指向具体 Circuit 时直接选中 Meter。Explorer → Overview 回到该 Meter 最近的模板 Scope，并保留 Period/Resource。URL 只负责导航，服务端仍重新解析权限与可信 Context。

## 4. AI Analyst

**任务：** 回答模板外的问题，并使计算过程可验证。

直接挂载 DataFoundry DataTasksApp，保留：

- 会话和追问；
- 文字、表格、图表；
- Artifact Preview；
- Task Console；
- Evidence、Trace；
- Files、Knowledge 引用。

来自 Overview/Explorer 的入口携带：

- Project；
- Scope；
- Tier；
- Resource；
- Period；
- Data/Hierarchy/Metric/Template 版本。

Task Console 展示范围解析、数据覆盖、使用的 Meter、差分/指标、查询和输出，不展示模型私有推理。用户在会话内改变 Scope/Time 时，服务端重新解析。

不复制 DataTasksApp，不使用 iframe，不在右下角再做一套完整聊天。

## 5. Data Map

**任务：** 让用户理解“数据从哪里来、如何连到当前分析”。

user 只读查看：

- Project/Tier/Scope；
- Meter Point；
- Source Binding；
- total/component/virtual 关系；
- business category；
- Metric 与 Knowledge 引用；
- configured/inferred 与可信状态。

admin 从后台进入编辑/诊断视图。

## 6. 角色动线

Boss：

~~~text
Overview → action/evidence → optional Explorer data verification → AI Analyst
~~~

FM：

~~~text
Overview exception → Explorer data/meter verification → AI Analyst
or Project Explorer → inspect data health/source → AI Analyst
~~~

两者权限相同。

## 7. 状态

| 状态 | UI |
| --- | --- |
| Draft Project | 仅 admin 可见 |
| Provisional metadata/mapping | 明确标签，不当作正式结论 |
| No data | 说明等待首次导入 |
| Partial | 展示覆盖率和受影响模块 |
| Stale | 显示最后成功日期 |
| Flatline | 显示“零耗能或疑似卡表”，不可直接等同离线 |
| Connectivity unavailable | 显示 Last data received，不伪造实时在线 |
| Failed run | 保留上次成功结果，可重试 |
| Insufficient history | 隐藏历史异常/Forecast |
| No tariff/area/people | 隐藏对应 Cost/EUI/per-person |

## 8. 当前原型与目标

当前已存在 Overview、Explorer、AI Analyst、Data Map、Admin 路由，AI Analyst 已复用 DataTasksApp，并有服务端 Energy Query Context 与样板事实。现有 Explorer 仍包含成本、横纵比较、业务异常与建议，这些属于待迁移到 Overview 的历史原型内容，不代表新的页面边界。

仍需：

- Tier Definition 取代自由 node_type；
- Meter Point 从空间节点分离；
- Ngee Ann 移除 Block Test；
- Preschool 区分 provisional Centre fixture 与三层目标；
- Project/Tier Template 和 Analysis Run 持久化；
- Explorer 收窄为来源数据与 Meter Data Health 核查，并补统一 Period Selector；
- Overview 接收跨节点比较、热力图、异常和建议；
- 去除硬编码 Tariff；
- 所有页面完全消费已发布配置。

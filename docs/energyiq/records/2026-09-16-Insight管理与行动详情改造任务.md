# Insight 管理与行动详情改造

## 已确认边界

- 先自由生成英文 HTML，再整理核心发现和行动；结构化清单不限制报告布局或分析深度。
- 默认一个发现、一个主要行动；底层保留一对多，操作步骤不拆成多个行动。
- 重复发现补充本期证据及报告来源，已有行动保留执行历史。不能只凭相同电表自动合并。
- Action 执行不等于 Insight 已解决；假设估算不等于实测效果。
- 不自动补提取旧报告，也不编造缺失的 Insight。

- Insight 独立生命周期、每期证据快照、重要性与紧急程度分离。
- 语义重复候选与确认合并；撤销、冲突及来源保留。
- 所有手动创建入口要求关联发现；已有共享行动的管理员关联表单已完成，个人行动关联仍待完善。
- 基于实际反馈更新优先级和经验；不自动把演示结果纳入正式校准。

## UI 设计

沿用应用的浅色、深绿操作色和现有字体。详情页只保留一个行动标题；下一步使用深色主按钮。来源证据和历史为次级内容，正文控制行宽，移动端纵向排列。默认主要行动突出，额外方案折叠，避免把 1:N 数据关系直接变成满屏卡片。

## 可撤销的发现合并

- [x] 同电表范围的发现可进入 Compare related findings。并排查看摘要、状态、行动数和原始引文；管理员选择保留的主发现，填写理由并明确确认。
- [x] 使用独立分组关系，不删除原发现、不移动 Action 归属、不合并 Action 身份。主发现的标题与评估保持，查询时汇集来源和行动；保留原发现信息。
- [x] Undo grouping 撤销关系，不回滚业务记录；合并后新增报告、评估和执行记录仍在。合并/撤销保存操作者、时间及原因。
- [x] UI 与 Agent insight_merge / insight_undo_merge 复用管理员权限接口。合并使用包含发现内容和行动关联的版本校验；请求幂等；拒绝跨项目、自合并、不同电表及嵌套分组。
- [x] 定向测试覆盖合并、撤销、越权、过期版本、失败保留草稿；API 和 Next 构建通过。
- 首版候选按相同电表范围筛选，不是自动语义去重，也不会自动合并。同一问题但电表范围改变，暂需进一步人工调查。一个分组暂支持两条发现，重新组合前先撤销。
- 撤销无需恢复旧快照，所以不会删除合并后产生的新资料。合并主条目的评估变化归主条目，原发现自身的评估保留。
- 本地 Tuya 两条现有发现分属 B05/B06，不应合并；本轮不为演示往项目灌入虚假重复发现，也不补提取旧报告。

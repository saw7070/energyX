# Insight / Action：聊天与网页共用操作

## 产品原则

用户可以点击页面，也可以告诉系统内的 Agent 自己做了什么。两种入口使用同一份 Insight / Action、执行记录和反馈，不维护两套状态。Agent 使用当前用户、当前项目的权限，不能指定另一个用户或项目来绕过授权。

## 连接方式

1. 正常报告通过现有报告产物注册流程，提取发现、建议及原文依据，关联项目 Insight / Action。
2. 聊天 Agent 调用列表工具，找到目标发现及行动，再读取当前版本和执行历史。
3. 用户提出假设时，调用估算工具保存 scenario。当前模型为可移除负载功率 × 每日减少小时 × 天数；电价可选。估算不会改变行动状态，也不是实测节能。
4. 用户明确表示计划或已执行后，调用进展工具，记录实际描述和时间。含糊的目标或时间先澄清；“准备做”不能记成“已执行”。
5. 检查效果工具使用现有实际读数与反馈工作流。数据不够时返回等待；足够时排入反馈生成任务。排队成功不等于报告已完成。
6. 后续读取行动可看到检查状态和反馈回执。网页与聊天都读取同一条行动。后续报告沿用项目行动进展与经验输入。

## 本轮接口

| Agent 工具 | 共用网页能力 |
| --- | --- |
| project_insights_list | 当前项目发现与行动关系 |
| project_actions_list | 可访问的项目行动，分页返回 |
| action_read | 当前版本、执行历史、检查状态、反馈回执 |
| action_estimate | 保存条件估算 |
| action_adopt_estimate | 明确选用一个估算以便之后比较 |
| action_record_progress | 计划、执行、暂停、不采纳；版本检查及重复请求去重 |
| action_check_effect | 检查真实读数，等待或安排反馈生成 |

工具调用复用 `handleActionApi`，并非通用 HTTP 代理。每次调用重新检查权限。仅普通交互聊天加载写工具；定时报告、反馈生成和提取专用任务不加载，避免自动分析自行“执行”行动。

## 分工与限制

- Prompt / Skill：规定分析方法、澄清条件、如何区分假设与观测。
- 工具与业务服务：负责授权、结构验证、版本冲突、记录保存、关联和审计。
- 工作流：负责等待可比读数、后台生成结果和后续报告携带进展。
- 人：执行物理动作，并如实提供时间、内容；Agent 不替人声称已经操作现场设备。
- 目前估算是限定的负载/时长计算，不是任意建筑措施的仿真引擎。
- mock 演示继续使用独立 Demonstration 流程，不能经真实执行工具写成已发生的行动。
- 本轮未开放任意删除、任意 Insight 合并或自动修改共享 Skill；这些操作要沿用各自业务约束。
